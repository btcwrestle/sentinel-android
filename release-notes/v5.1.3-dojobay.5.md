# v5.1.3-dojobay.5

First build from the new tag-driven release pipeline: the APK is built and
signed from the tagged commit, and the app reports the tag as its version,
so a build can no longer claim a version it isn't. Two bigger changes ride
along and get special attention below: the release variant is now minified
(R8), and the local database is encrypted.

## Fixed since v5.1.3-dojobay.4

- A failed automatic sync no longer wipes UTXOs (#287), and an empty fetch
  no longer wipes history unless the sync round was healthy (#226).
- Keychain transaction history now appears on first open after a sync,
  instead of needing the back-out-and-reenter dance (#284).
- Sync writes are batched into single transactions with one UI update per
  round, and labels run after inserts — no more mid-sync flicker or the
  "history briefly empty" window (#198, #201, #202).
- Fiat display took several passes in this window; together they add up to:
  balances re-render when street mode or the rate changes (#235), fiat
  shows under BTC and sats with hide-fiat hiding both, the cached total
  shows while sync runs, and hide-fiat clears the line instead of leaving
  00.00.
- Tor now fails closed: pairing and the explorer webview refuse to talk
  until the SOCKS proxy is up, TLS stays strict on clearnet and relaxes
  only for .onion (#229, #233, #240-#242 — the explorer crashed once with
  the first pass of this work and was re-fixed, PR #253).
- Debug logcat no longer leaks wallet material: pairing details, txids,
  onion hosts, and xpub prefixes are masked at the logging boundary
  (#258, #264, #96); debug HTTP wire logging stays available behind it.
- Dojo pairing is confirm-first with a readable pre-pair summary, a
  post-pair receipt, and stricter payload validation — nothing is written
  or contacted before the user says go (#234, #250, #256, #260, #261).
- Bottom sheets, scanned payloads, the sweep preview, and Collection
  Details survive activity/fragment recreation (#210, #215-#218, #221),
  and restored activities must pass the lock before reading (#300).
- QR and import: one invalid-payload policy — a single toast, camera never
  strands (#232); one dispatch per decoded frame (#246-#248); multi-key UR
  and legacy Dojo imports no longer drop keys silently (#254, #276);
  cross-network imports are refused instead of mixed in (#272).
- Network page gained a Mainnet/Testnet switch (#208).
- Send/Sweep: PSBT change derivation no longer lands on output 0, Whirlpool
  remixes route hands-off to the writer, fee tiers no longer store High as
  Normal (#305), and the sweep key-entry fragment got its own name (#280).
- Storage: the local database is encrypted and the PIN/backup format was
  modernized; legacy v2 backups with the SHA-256 iteration count still
  decrypt (#278).
- Smaller fixes: Whirlpool autolabel casing matches Ashigaru's "Tx0",
  Ashigaru branding renders on imported keychains (#162), the details
  pager rebuilds only on real key changes (#204), collection edit keeps
  existing keys on duplicate add (#243, #244), Dojo response bodies are
  closed, durable PIN flows and the Dojo setup listener (#220), plus the
  stale network row, BIP89 deposit typo, and autolabel copy trio
  (#274, #219, #225).

## Worth a specific check

1. R8 minification is new. The test suite runs on the debug variant and
   cannot see shrinking or obfuscation problems, so a normal hands-on pass
   — pair, sync, open a keychain, send-flow preview, import, settings —
   is the real test of this change.
2. Database encryption plus the new PIN/backup format: update an existing
   install in place (do not uninstall), confirm PIN unlock still works,
   then round-trip a backup export and import on this build.
3. Tor fail-closed: with Tor not ready, pairing and the explorer must
   refuse rather than connect; once ready, the explorer webview must open.
4. minSdk moved from 23 to 24 (#236): Android 6.0 devices can no longer
   install this build — flag it to anyone testing on old hardware.
