# v5.1.3-dojobay.7

One fix since v5.1.3-dojobay.6: fiat rates come back over Tor.

## Fixed since v5.1.3-dojobay.6

- Fiat values never rendered anywhere (#338): every clearnet HTTPS call
  through Tor died in the TLS handshake. TlsPolicy's strict path delegated
  host-blind (checkServerTrusted(chain, authType)), and Android refuses
  that entry under this app's per-domain network security config. Rate
  fetches are the app's only regular clearnet HTTPS traffic, so fiat
  starved while all Dojo traffic over onion kept working. The strict path
  now routes through the hostname-aware platform entry
  (android.net.http.X509TrustManagerExtensions) with one host string
  feeding both the relax decision and the verification (#339). Onion
  relaxation, the fail-closed Tor gates, the hostname verifier, and all
  install call sites are untouched - clearnet over a Tor exit now gets
  real verification, which completes the #230 design rather than
  weakening it.

## Worth a specific check

1. Update a paired install in place over .6 (do not uninstall), Tor on,
   cold boot: a fiat number should appear under the BTC total on Home
   once Tor is up. The device leg that closed #338 proved this on a
   debug rebuild at the same versionCode; this is the first tagged,
   release-signed build carrying the fix.
2. Switching exchange or currency should now visibly take effect; before
   the fix all three providers failed identically, so switching looked
   dead.
3. The handshake must stay strict: clearnet HTTPS through a Tor exit
   still verifies against the platform trust anchors. A regression here
   shows up as SSLHandshakeException deaths in logcat.

## Known not to work (pre-existing, censused in #338 - not this build)

- CryptoCompare returns 401 without an API key; CoinGecko and CexIo are
  the live providers.
- CexIo decimal prices will fail its parser.
- Opening Settings wipes the stored rate until the next fetch.
